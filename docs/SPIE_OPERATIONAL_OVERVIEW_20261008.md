# SPIE operational overview · 2026-10-08

The existing SPIE workspace remains the owner. Overview now places current communication, actions, order/production/shipment states, financial payment aggregates, guarantees, deadlines and missing required documents in one vertical surface. Unknown and failed reads remain explicit. Currency totals are separate and no accounting or pipeline inference is made from email.

Google reads use the existing authenticated PPPP/Google sessions. Four exact canonical or approved context thread identities plus the existing precise TenneT search discover new replies. External messages are display-only and labeled as absent from PPPP. A project context fact named spie.workspace.communication_threads.v1 can provide verified additional thread identities; filenames, domains and subject alone do not canonicalize third-party threads.

The page refreshes every two minutes only while visible, with no open dialog or active route read. Reads coalesce; finance and action reads are non-blocking. Manual refresh is available. This is browser freshness, not a replacement for backend ingestion.

spie/evidence.mjs renders email plain text safely and opens small PDF/image/text files on demand. Download responses are bounded to 10 MB. Other formats or large files use an in-module Drive preview where a verified Drive identity exists. There is no permanent browser copy, Gmail body persistence, HTML email execution or database write.

Create document is available on every workspace view: offer, invoice, credit note, debit note and official letter. Existing canonical commercial editors, numbering, role approval and read-back verification remain intact. Debit notes use the existing adjustment owner with the correct positive sign and do not receive the credit-only balance cap. Official letters use the existing context-fact bridge, manual reference, explicit approval and verified read-back before PDF or Gmail draft becomes available. No email is sent automatically.

New documents share the official logo. Older saved model versions remain accepted; their source layout is retained. The logo asset is extracted from the existing application LOGO_BASE64. The newly uploaded logo/icon could not be accessed under current tool approval policy, so those replacements remain pending.

No schema, finance records, project state, Google tokens, Drive folder or ingestion worker is modified.
